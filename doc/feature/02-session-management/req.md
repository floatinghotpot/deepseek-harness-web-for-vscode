## 1. 背景（一句话）

扩展当前是**单面板单会话**（`DshPanel` 单例，`open()` 只 reveal 不新建）；DSH 协议层已支持单实例多会话并行，本特性补上**壳层的会话编排 UI**——会话管理器侧边栏 + `＋新建会话` 开新面板绑新会话，让"多工作区/多模型 = 多会话"真正可用。

## 2. 范围（做这 2 项主需求）

### R1 — 会话管理器侧边栏（G-12）

- 在启动器（launcher）内增加**会话管理区**：
  - 顶部保留进程状态（现状复用，不重做）；
  - `＋新建会话` 按钮（全宽，次级按钮样式）；
  - **会话列表**：列出当前工作区的会话，每项显示**会话标题**（同工作区**不显示 cwd**）与**相对活跃时间**（`5m`/`3h`/`2d`，对齐 DSH 官方 `relativeTime` 分桶；数据来自 `session.list.updatedAt`，零额外调用），每项带 `✎`（重命名）与 `🗑`（归档会话）按钮；模型信息在面板内 DSH UI 可见，列表不展示；
  - 会话标题 = `session.list` 的 `projections.values.title`；未命名（`null`）时降级显示 cwd basename 或会话 id（对齐 DSH 前端 `displayTitleOf` 逻辑）；
  - 归档会话（`archivedSessionIds`）与活跃会话分区展示（文字区分，不展开）。
- **重命名**：点 `✎` → 输入新标题 → `session.rename {sessionId, title}`（过 `/api` 围栏，已实测可行）→ 列表刷新显示新标题；空标题/超长由服务端归一化拒绝（`title-invalid`），UI 提示不崩溃。
- **数据源**：扩展侧 Node 直连 `session.list` / `workspace.list`（复用 `ensureWorkspaceSession` 的中继路径，过 `/api` 围栏）。
- **验收**：
  - 打开侧边栏可见会话列表（无会话时显示空态 + `＋新建会话` 引导）；
  - 会话项显示标题（有标题显示标题；无标题显示降级名）；同工作区会话不显示路径；
  - 点 `✎` 重命名 → 列表与 DSH UI 内标题同步更新；空标题被拒绝且有提示；
  - 点 `🗑` 归档 → 会话从活跃列表移入归档分区（DSH 归档为 append-only，扩展侧过滤活跃列表）；对应打开面板关闭；**会话不删除**（可恢复）；
  - 归档与活跃分区正确（对齐 `workspace.list` 返回）；
  - 列表随会话增删**刷新**（手动刷新按钮或自动轮询，见决策 D1）。

### R2 — 多面板绑定多会话

- `＋新建会话` → `session.create {workspaceId}`（复用 `ensureWorkspaceSession` 的 workspace 解析）→ **打开新的编辑器面板**，preset 注入指向新会话（复用 feature 01 T7d 注入机制）→ DSH UI 首屏即显示该会话；
- 多个面板**并存**（`WebviewPanel` 多实例），各自独立会话，互不影响（`agent-busy` 只拦同会话，协议层已保证）；
- 面板关闭（编辑器标签页原生 `✕`）**不杀会话**（对齐 R5 不杀进程语义）；会话在 DSH 内保留，可从列表重新打开。
- **验收**：
  - 点 `＋新建会话` → 新面板打开且显示新会话（非"最近活跃"会话）；
  - 连续创建 2+ 个面板并存，各自会话独立，流式输出互不干扰；
  - 关掉某个面板标签页 → 会话不消失，侧边栏列表仍在，可从列表再次打开该会话；
  - 同工作区普通重载后：自动重启 dsh + **恢复全部已开面板**（各自绑定原会话，复用 feature 01 wasRunning 机制扩展）；
  - 降级可接受：preset 注入失效 → 该面板退回"最近活跃"行为（不崩、不报错）。

## 3. 决策项（req 评审时确认，默认值见括号）

| # | 决策项 | 默认建议 | 备注 |
|---|---|---|---|
| D1 | 会话列表刷新方式 | **轮询** `session.list`（5s 间隔，仅面板可见时） | 简单可靠；WS 推送依赖事件帧格式，MVP 不做 |
| D2 | 面板↔会话绑定归属 | 扩展侧 `Map<panelId, sessionId>` + 重建面板时 preset 重注入 | localStorage 按面板 origin 的隔离性需 Spike 验证（discussion §5） |
| D3 | 面板关闭语义 | 仅关面板（编辑器标签页原生 `✕`），**不杀会话**（2026-08-19 F5 反馈：列表内 `✕` 移除，保留 `🗑` 归档） | 会话删除依赖 DSH 是否有 `session.delete` API——Spike 确认，MVP 默认不做删除 |
| D4 | `＋新建会话` 交互 | 直接开新面板，**不弹模型选择** | 模型在 DSH UI 内选（壳层不重造前端交互） |
| D5 | 会话列表范围 | 当前工作区会话 + 归档分区 | 对齐 `workspace.list` 结构 |
| D6 | 多面板数量上限 | 无硬限 | 用户自行管理标签页 |
| D7 | 重命名输入方式 | 点 `✎` 后**列表内 inline 编辑**（输入框 + 回车确认 / Esc 取消） | 对齐 VS Code 资源管理器 F2 惯例；不弹新窗口 |

## 5. 约束（必须遵守）

- **C1 零改动 DSH**：不 fork、不修改 DSH 源码；只调用既有 `session.*` / `workspace.*` API；
- **C2 安全底线**：服务仅绑回环；不弱化 `/api` 信任围栏；webview 有严格 CSP；
- **C3 语言**：新增用户可见文案中英双语（9 语言 i18n 表补齐）；
- **C4 流程**：本 req 批准后，先写 solution.md + plan.md，再实现；实现中每 2–3 个任务对照本 req 自审。

## 6. 验收总则

- **完成 = R1 + R2 全部验收通过**；N1–N6 不实现不阻塞；
- 前置 Spike（solution 前）：验证多面板 localStorage 隔离性、`session.list` 返回结构（标题/running/archived 字段）、`session.delete` 是否存在；
- 单测重点：会话列表数据解析（含 `projections.values.title` 读取与 null 降级）、重命名请求构造（标题转义/拒绝处理）、面板↔会话映射、preset payload 构造（复用 `buildSessionPresetPayload`）、多面板生命周期；
- 全量 `npm test` 绿 + `npm run compile`（tsc strict）零 issue；跨平台 CI 三平台绿。
