## 1. 背景（一句话）

MVP 已把 DSH Web UI 内嵌进 IDE（单实例、单面板、cwd=工作区）；本特性让扩展具备**会话级**能力：可视化会话管理（G-12）、工作区切换联动（G-02）、dsh 版本软校验（G-03）——落实"桥"定位中**心智连续**与**高效便捷**两价值层。

## 2. 范围（做这 3 项）

### R1 — 会话管理器侧边栏（G-12）

- 侧边栏提供**会话管理器**视图：顶部 dsh **进程状态** + `＋新建会话` 按钮 + **会话列表**（每行显示模型名与 `✕`）。
- **UI 示意（文本 demo）**：

  ```
  ┌──────────────────────────────┐
  │ DeepSeek Harness             │  ← 侧边栏标题（与现有启动器同活动栏）
  ├──────────────────────────────┤
  │ ● dsh 运行中                 │  ← 进程状态（未运行: ○ dsh 已停止）
  │   127.0.0.1:43821            │
  ├──────────────────────────────┤
  │ [ ＋ 新建会话 ]               │  ← 无进程→起并建会话；有→直接开会话
  ├──────────────────────────────┤
  │ 会话                         │
  │  ┌────────────────────────┐  │
  │  │ 💬 deepseek-chat  [✕]  │  │  ← 模型名（区分多模型会话）
  │  ├────────────────────────┤  │
  │  │ 💬 deepseek-reasoner ✕ │  │  ← ✕ = 关编辑器标签页
  │  └────────────────────────┘  │       （会话持久保留，不删除）
  └──────────────────────────────┘
  ```

- 语义：
  - `＋新建会话`：无进程时启动 dsh 并新建会话；已有进程时直接新建会话（单实例多会话）；
  - 会话列表每行 `✕` = **关闭对应编辑器标签页**（DSH 会话**持久保留**，不删除会话）；
  - 关闭编辑器标签页 ↔ 会话列表同步消失；
  - 会话默认绑定当前工作区（不显示 cwd）。
- **验收**：
  - 会话管理器出现在侧边栏，与现有启动器不冲突（布局不重叠）；
  - 多会话场景下列表正确列出各会话（含模型名），新建/关闭标签页后列表实时刷新；
  - `✕` 只关标签页，DSH 内会话仍存在（切换回工作区可见）；i18n 文案补齐 9 语言。

### R2 — 工作区切换联动（G-02）

- 监听 IDE 工作区切换（`onDidChangeWorkspaceFolders` + activate 时比对上次 workspace 路径）：
  - **关闭所有 dsh4vscode 面板**：旧面板承载的是**旧工作区的会话**，切换后一律关闭，不留旧工作区状态在界面上；
  - **不杀 dsh 进程**（会话级切换）：旧工作区会话组在 DSH 内**归档保留**（`~/.dsh` 持久，不删除、不迁移），切回旧工作区可恢复；
  - **工作区已变 → 不自动重启/不自动开面板**：新工作区由用户点 `＋新建会话` 启动——无进程则起 dsh（cwd=新工作区）并建会话，有进程则直接开会话（绑定新工作区）；
  - **工作区未变（普通重载：改设置/装扩展/更新）→ 仍自动重启 dsh 并恢复面板**（A2 保留，不打断连续性）；区分依据 = 存储的上次 workspace 路径 vs 当前路径。
- **UI 示意（文本 demo）**：

  ```
  切换文件夹 A → B（窗口重载；dsh 随扩展宿主结束，面板全部关闭）

  之前（工作区 A）                之后（工作区 B，用户操作前）
  ┌───────────────────────┐      ┌───────────────────────┐
  │ ● dsh 运行中          │      │ ○ dsh 已停止          │ ← 不自动起
  │ 会话                   │      │ 会话                   │
  │  💬 deepseek-chat     │      │  （无面板，全部已关闭） │ ← 旧面板已清
  │  💬 deepseek-reasoner │      │  [ ＋ 新建会话 ]        │ ← 用户点这里
  │  （编辑器标签页 ×2）   │      │                       │
  └───────────────────────┘      │  ── 归档（DSH 内）──   │
                                 │  [A] 会话组（保留可恢复）│ ← 不删不迁
                                 └───────────────────────┘
  ```
- **验收**：
  - 切换工作区后：旧 dsh4vscode 面板全部关闭，无残留展示旧工作区会话的标签页；
  - 扩展不因切换主动杀 dsh（窗口重载导致的自然终止除外）；旧会话组在 DSH 内归档保留，切回旧工作区可恢复；
  - 新工作区点 `＋新建会话`：无进程时起 dsh（cwd=新工作区）并建会话；有进程时直接开会话（绑定新工作区）；
  - 同工作区普通重载：自动重启 dsh 并恢复面板（A2 连续性）；
  - 全程无静默破坏：无会话被删除/迁移，cwd 绑定不被意外改动。

### R3 — dsh 版本软校验（G-03）

- dsh 启动后核对版本（`dsh --version`）：
  - 版本 < **0.1.0-rc.6**（目标基线）→ **UI 警告**（状态栏/通知，提示升级），不阻断使用。
- **UI 示意（文本 demo）**：

  ```
  VS Code 窗口（低版本 dsh 时）：

  ┌───────────────────────────────────────────────────────────────┐
  │ 编辑器区域（文件标签页…）                                       │
  │  ┌─────────┬─────────┐                                         │
  │  │login.ts │auth.ts  │                                         │
  │  └─────────┴─────────┘                                         │
  ├───────────────────────────────────────────────────────────────┤
  │ ⚠ dsh v0.1.0-rc.3 过旧 · 升级说明            ⎇ main · 第 42 行 │  ← 状态栏
  └───────────────────────────────────────────────────────────────┘

  状态栏（窗口底部整条）内的警告项：
  左侧：⚠ dsh v0.1.0-rc.3 过旧，建议 ≥0.1.0-rc.6
  右侧：升级说明（点击 → 打开升级指引）
  ```
- **验收**：
  - 低版本 dsh 环境：启动后出现明确升级提示；
  - 达标版本：无警告；版本探测失败（如命令异常）→ 静默降级（不误报）。

## 4. 约束（必须遵守）

- **C1 零改动 DSH**：不 fork、不修改 DSH 源码；只调用既有 `session.*` / `workspace.*` API。
- **C2 安全底线**：服务仅绑回环；不弱化 `/api` 信任围栏；webview 有严格 CSP。
- **C3 语言**：新增用户可见文案中英双语（9 语言 i18n 表补齐）；文档中文（仓库约定）。
- **C4 流程**：本 req 批准后，先写 solution.md + plan.md，再实现；实现中每 2–3 个任务对照本 req 自审。

## 5. 验收总则

- **完成 = R1–R3 全部验收通过**；N1–N6 不实现不阻塞。
- 单测重点：会话列表刷新逻辑、工作区切换的会话组归档/新建、版本解析与降级；跨平台 CI（macOS/Linux/Windows）全绿。
